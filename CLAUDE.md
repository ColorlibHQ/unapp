# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Unapp 2.5.1** is a Colorlib **WordPress block theme** (Full Site Editing) with **thirteen one-click starter sites** (SaaS, portfolio, church, blog, fitness, restaurant, agency, shop, property, practice, courses, conference, finance) — 143 section patterns, 19 page starters, 22 templates (six of them WooCommerce), 7 section styles, 11 block styles, and 12 colour palettes × 5 typography presets — text domain `unapp`, upstream `github.com/ColorlibHQ/unapp`. Version 2.0.0 (Aug 2026) is a from-scratch rewrite: the Epsilon Framework, Customizer section builder, Bootstrap 3, jQuery and icon fonts from 1.x are gone. It is *not* a static HTML template — the Colorlib R2 preview/download publishing flow and the HTML-template upgrade phases in the global instructions do not apply here.

Requires WP 6.6+ (theme.json v3, section styles); tested on WP 7.0. No build step, no npm, no SCSS — every file is committed as-is.

### Conventions that matter

- **Section wrapper**: every section pattern is `<!-- wp:group {"align":"full","layout":{"type":"constrained"}} -->` with **only top/bottom padding**. `useRootPaddingAwareAlignments` is on, so alignfull constrained groups get left/right padding from root padding automatically (WP adds `has-global-padding`); adding L/R padding double-pads. Section intros use a nested constrained group with `contentSize: 680px`; grids use `align: wide` (1200px).
- **Colours in patterns are palette slugs only** (`textColor:"muted"`, `backgroundColor:"primary"`, `gradient:"primary-to-accent"`) so the color variations restyle everything. The exceptions are white-on-gradient/dark contexts using `rgba(255,255,255,…)` custom colors. Section styles `section-dark`/`section-gradient` redefine `--wp--preset--color--muted` and `--border` via their `css` key so `has-muted-color` text stays readable on dark backgrounds.
- **Icon badges** are a flex Group (background primary/secondary, radius, 12–14px padding) containing a `core/image` pointing at `assets/images/icons/*.svg` (white-stroke Feather icons). Wrap in a vertical-flex column or a flex row so the badge shrinks to content.
- **Repeated items are generated in PHP** (`$unapp_services`, `$unapp_plans`, `$unapp_members`…) with `_x()` in the array and `esc_html()` at output — keep that pattern; do not echo unescaped strings.
- **Block markup must be valid** in the editor. Serialized classes/styles must match what the block's `save()` produces (`has-{slug}-color has-text-color`, `has-{slug}-font-size`, `is-resized`, `has-custom-border`, `alignwide`, …). Cover uses the older *span-before-img* markup on purpose: it validates via deprecation on 7.0 and natively on 6.6. Verify with `wp.blocks.parse(content)` in an editor tab (walk `innerBlocks`, look for `isValid === false`) — the site-editor UI does not reliably surface invalid theme-file blocks, and a paragraph with a `<div>` is *not* flagged, so use heading/button/image probes when sanity-checking the checker.
- **Stats counter**: paragraphs with class `unapp-count`; `functions.php` enqueues `assets/js/counter.js` (defer, footer) from a `render_block_core/paragraph` filter only when such a paragraph renders. Number formats supported: `10,000+`, `1.2M`, `99.9%`, `4.9/5` (prefix/number/suffix regex).
- **Front page**: no HTML template. `inc/front-page-setup.php` hooks `after_switch_theme` (fires on `init` 99) → sets a pending flag → `init` 100 runs `unapp_setup_front_page()`: expands `unapp/page-home` (nested `wp:pattern` refs resolved by `unapp_get_pattern_markup()`), inserts a published "Home" page (template `page-no-title`, kses filters temporarily removed) and a "Blog" page, sets `show_on_front/page_on_front/page_for_posts`, records IDs in option `unapp_front_page_setup` (never re-runs). Automatic only when the site has no static front page; otherwise option `unapp_offer_front_page_setup` shows an admin notice with an admin-post button (nonce + `edit_theme_options`). Filter `unapp_auto_setup_front_page` disables auto-run. `home.html` is the posts page.
- **Hidden patterns** (`Inserter: no`) carry translatable text for templates: `hidden-blog-heading`, `hidden-posts-grid`, `hidden-search`, `hidden-404`, `hidden-post-meta`, `hidden-post-tags`, `hidden-comments`. Page starters (`page-home`, `page-about`, `page-pricing`) are `wp:pattern` lists in category `unapp_page` with `Block Types: core/post-content`.
- Pattern categories registered in `functions.php`: `unapp` (everything), `unapp_hero`, `unapp_features`, `unapp_proof`, `unapp_pricing`, `unapp_cta`, `unapp_content`, `unapp_company`, `unapp_utility`, `unapp_page`; core categories are used alongside them.
- **There is one measurement system, and `pgen.py` holds it.** `SECTION_PAD=("70","70")`, `SECTION_GAP="60"`, `CARD_PAD="50"`, `CARD_GAP="30"`, `ROW_GAP="40"`, `STACK_GAP="30"`, `CARD_RADIUS="20px"`, `INTRO_WIDTH="680px"`, `READ_WIDTH="760px"`, avatars 56/96/140px. Build sections from the components (`section_std`, `card`, `stack`, `grid`, `split`, `icon_card`, `card_title`, `label`, `faq_list`, `band`) rather than passing raw numbers — that is what keeps a church page and a SaaS page on the same rhythm. Three radii exist in the whole theme: 14px (icon badges), 20px (cards and images), 999px (pills and avatars).
- **`sp()` refuses spacing that is not on the scale.** theme.json registers only 20–80 in tens; `var(--wp--preset--spacing--16)` is undefined, so WP drops the declaration and the element silently falls back to its inherited gap. That single mistake — 55 declarations across the niche patterns — was what made the 2.3 starter sites look arbitrarily spaced. Pass a registered slug, or an explicit length (`"0"`, `"12px"`) when you mean one.
- **Verify rhythm by measuring, not by eye.** `.dev/cdp-rhythm.mjs` renders each pattern, measures every gap between sibling blocks and flags any that is not on the scale (resolve the presets by measuring an element — they are written in `rem` and `clamp()`, so `parseFloat` gives nonsense). The whole library reports 0/101 off-scale.
- **Sections alternate grounds by role**, applied by `.dev/apply_grounds.py`: explanation sits on the page ground, proof/prices/answers/contact on `is-style-section-soft`. `.dev/rhythm_audit.py` checks every composition (demo homes, page starters, starter pages) and fails on four sections sharing a ground or two full-bleed bands in a row. Where two same-ground sections do meet, `style.css` draws a hairline seam so they do not read as one column.
- **Patterns are generated, not hand-typed.** `.dev/pgen.py` emits PHP pattern files from composable block emitters — `section()`, `intro()`, `columns()/column()`, `icon_badge()`, `buttons()`, `lst()`, `image()`, `group(border_top=…)` — so every pattern uses markup that matches core's `save()`. When adding a pattern, extend the generator rather than writing markup by hand, then re-run the batch script and re-validate.
- **No orphaned wraps.** A flex/grid row must never leave a single item alone on the last line. WP's grid layout keeps one column count at every width, so use the `unapp-grid-4` / `unapp-grid-3` utility classes (in `style.css`) alongside `columnCount`, which step down through counts that divide the item count evenly. `.dev` tooling: the wrap audit script groups children by vertical *overlap* (not exact `top`, which false-positives on rows of mixed-height items) and flags `orphan` (last row = 1) and `ragged` (last row < full row).
- **Footers show the site tagline, with the written line as a fallback.** Every footer's brand column wraps its short line in `<?php if ( get_bloginfo( 'description' ) ) : ?>` — `core/site-tagline` when the site has a tagline, the hard-coded copy when it does not. Do not "simplify" that back to one branch: without the fallback a fresh install shows an empty footer column, and without the tagline branch the setup wizard asks for something nothing renders (the original GitHub issue #22, live from 2019 until 2.5.1).
- **The style engine drops `rgba()` from a dynamic block's colour attribute.** `<!-- wp:site-tagline {"style":{"color":{"text":"rgba(255,255,255,0.75)"}}} /-->` renders `class="… has-text-color"` with no `style` at all, while `#hex` passes through. Static blocks are unaffected because their colour is already in the saved markup — which is why the footer paragraphs can use `rgba()` inline but the tagline takes `.unapp-footer-note` from `style.css` instead.
- **The header is a single line by contract.** `patterns/header.php` carries `unapp-header-row`; `style.css` sets it `nowrap`, keeps nav items on one line, and moves core's overlay-menu breakpoint from 600px up to 1000px. Do not remove those rules — without them a six-item menu plus the CTA button stacks into three rows on tablets.
- **A theme must not process form submissions.** `inc/forms.php` detects whichever form plugin is active (ten are recognised), renders its first form, and wraps the output in `.unapp-form` so `assets/css/forms.css` can style the fields without knowing each plugin's class names. Detection prefers a registered post type over a class name — plugins move their namespaces between versions, the post type does not. Extend via `unapp_form_providers` / `unapp_detected_form`.
- **Starter pages are locked to their content.** `unapp_lock_starter_sections()` marks every top-level section `contentOnly` when a starter builds a page, so text and images stay editable and the scaffolding does not move. `core/cover` accepts the attribute but does not pass it to its inner blocks, so a Cover hero stays fully editable.
- **Dark mode lifts the palette, it does not replace it.** `assets/css/scheme.css` computes the lifted colours on `html` and consumes them on `body`: doing both on one element makes each custom property depend on itself, which is invalid and silently dropped. Sections with their own dark ground (gradient bands, the dark footer, covers) get `base`/`contrast` put back to their light-mode meaning, or their text inverts. 52% is the most colour that clears 4.5:1 on the dark ground for all twelve palettes.
- **WooCommerce sizes its product grid against its own gap.** Woo uses `auto-fill` with `minmax(max(150px, calc(33.33% - .83em)), 1fr)`, which assumes its 1.25em gap; widening the gap to the theme's spacing scale silently drops three columns to two. `assets/css/woocommerce.css` sets the tracks explicitly and steps them 3 → 2 → 1.
- **The header row is `nowrap`, so its children must be allowed to shrink.** Below 600px `style.css` sets `min-width: 0` on the groups, truncates the site title and tightens the button padding and gaps — otherwise a long CTA label, or WooCommerce adding account and cart icons, pushes the button past the viewport. The button's padding is set inline by the header pattern, so only `!important` reaches it.
- **Starter sites** (`inc/starter-sites.php`) are the demo system: each definition names a curated style variation, a home pattern, a `footer` pattern, supporting pages, swatches and a header CTA label. `unapp_apply_starter_site()` creates pages, writes the variation into the user's `wp_global_styles` post, rebuilds the `wp_navigation` post, saves a customised `header` template part when the CTA differs from the theme default (and deletes that part when it matches again), and points the `footer` part at the starter's own footer pattern via `unapp_set_part_to_pattern()`. It never deletes user content. Extend via the `unapp_starter_sites` filter.
- **A starter page is a list of sections**, not one pattern: `'patterns' => array( 'unapp/church-visit', 'unapp/church-times', … )`, concatenated by `unapp_get_starter_page_markup()` (a single `'pattern'` key still works). Missing patterns are skipped, so a page still renders where a block is unavailable.
- **Every niche owns its whole page.** A starter must not borrow a section whose copy is written for another kind of site — that was the 2.3 bug: the church home shipped `unapp/team` ("Dorothy Murphy, Product Designer") and `unapp/offices` (three sales offices), and its Contact page ended in a SaaS FAQ about 14-day trials. When a starter needs a people/FAQ/contact/CTA section, write `{niche}-staff`, `{niche}-faq`, `{niche}-contact`, `{niche}-cta` rather than reusing the SaaS one. The shared footer is part of "the whole page" — hence `footer-{niche}.php`.
- **Niche patterns** are prefixed by niche (`portfolio-*`, `church-*`, `fitness-*`, `finance-*`, `blog-*`) and categorised `unapp_portfolio` / `unapp_church` / etc. The six `demo-*` patterns are their home-page compositions.
- **Capturing previews of `vh` heroes**: never resize the viewport to the full page height — `min-height: 64vh` then resolves against that height and the hero fills the screenshot. Keep a realistic viewport and pass `captureBeyondViewport: true`.
- **Theme Check text-domain false positive**: an array access with a string key inside a translation call (`_n( '…', '…', count( $site['pages'] ), 'unapp' )`) makes Theme Check report a second text domain. Assign the count to a variable first.
- **Style variation partials are all-or-nothing.** The Site Editor lists a variation under Colors or Typography only if `isVariationWithProperties` finds *nothing else* in it (edit-site filters the object to that property and compares `styles` + `settings`). A stray `settings.shadow` in a colour partial silently demotes it to a full variation. That is why shadows live in `theme.json` and are built with `color-mix()` on palette colours so they follow whichever palette is active.
- **New-in-7.0 blocks degrade, they don't break.** `core/accordion`, `core/breadcrumbs`, `core/query-total` and `core/post-time-to-read` are used in patterns and templates; `unapp_unregister_unsupported_patterns()` hides patterns whose blocks are missing and `unapp_skip_unsupported_blocks()` renders nothing for the rest, so the theme still runs on 6.6.
- **`core/icon` is not usable for the theme's icon set.** WP 7.0 ships the block and an icon registry, but `WP_Icons_Registry::register()` is `protected` — there is no public API for a theme to add icons, and core registers only 88 generic ones (`core/check`, `core/people`, `core/star-filled`…). Converting the badges would drop roughly 35 of the 55 Feather icons the theme uses. The badges stay as `core/image` pointing at `assets/images/icons/*.svg`, which users can still swap through the Image block's replace control. Revisit when core opens registration.
- **Get canonical markup from the editor, don't guess it.** The Accordion sub-blocks source their title from `.wp-block-accordion-heading__toggle-title` inside a button. The reliable way to author markup for an unfamiliar block is `wp.blocks.serialize(wp.blocks.createBlock(...))` in an editor tab — that is how `faq-accordion.php` was written.
- **Buttons take their background from `secondary` and their text from `contrast`** (`theme.json`). Any new palette therefore needs a `secondary` that is mid-toned: too pale and the call to action reads as disabled (Mono's `#e8e6e1`), and in a *dark* palette `contrast` is light, so the button needs `styles.elements.button.color.text = base` or it fails contrast outright (Midnight was 1.73:1). `styles.elements.button.color` still counts as colour-only, so it can live in a `styles/colors/*.json` partial.
- **On a dark or gradient section, colour headings and outline buttons explicitly.** `theme.json` sets `elements.heading.color.text` to `contrast` (near-black), so a heading on a dark ground disappears. Either set `textColor: base` on the heading (what `cta-band.php` does) or override `elements.heading`/`elements.link` on the section group (what `footer.php` does). Outline buttons need `textColor: base` too.
- **Three markup rules the validator caught during the 2.1 build**, worth remembering: (1) never emit raw inline CSS that no block attribute backs — e.g. `style="opacity:…"` on a Group fails validation; use a `className` plus theme CSS. (2) An icon badge (flex Group) stretches full width inside a `default`-layout parent; put it in a parent with `layout: flex, orientation: vertical`, which WP renders as `align-items: flex-start`. (3) A Query Loop with `sticky: ""` prepends sticky posts *on top of* `perPage`; use `sticky: "exclude"` for featured/list layouts.
- **New pattern files are cached.** `WP_Theme::get_block_patterns()` caches the file scan per theme, so a newly added `patterns/*.php` will not appear until the cache is cleared. The Local site now has `WP_DEVELOPMENT_MODE = 'theme'` in wp-config.php, which bypasses that cache — keep it while developing patterns.
- **Alignment model**: post content is `alignfull` + constrained, so core floats `.alignleft/.alignright` direct children to the *container* edge (= viewport). `style.css` pulls them back with `margin-inline-start/end: max(0px, calc((100% - content-size) / 2))`. Verified ladder on `/block-image/`: normal l=300 w=800, alignwide l=100 w=1200, alignfull l=0 w=1400 at a 1400px viewport.
- **Classic content** (freeform HTML, shortcodes) gets no blockGap, so `style.css` supplies the rhythm and styles `[gallery]`/`[caption]`/floats/tables/pre/dl to match block output. Selectors are scoped with `:is(.wp-block-post-content, .wp-block-comment-content, .editor-styles-wrapper)` — in the iframed editor the canvas `<body>` carries `editor-styles-wrapper` and theme CSS is injected unprefixed, so the same rules work in both places. Elements rendered by blocks carry a `wp-block-*` class and are excluded via `:not([class*="wp-block-"])`.
- Core's `is-style-squared` button style targets the *wrapper* while global styles put the radius on the link, so the theme re-applies `border-radius: 0` to the link.
- **Root padding values need units** (`"0px"`, not `"0"`): WP 7.0's navigation overlay uses `clamp(1rem, var(--wp--style--root--padding-top), 20rem)`; a unitless `0` makes the whole padding declaration invalid and the mobile menu loses all padding.
- **theme.json nested `css` strings**: WP splits on `&`, so `& a, & b{…}` breaks (the comma part becomes a bogus root rule). Write one `&` rule per selector.
- **Testing recipe used for 2.0.0**: activation flows via wp-cli (`theme activate` fires the setup within the same CLI run), admin flows/screenshots via headless Chrome + CDP (login with `wp-login.php?redirect_to=…` so the dashboard doesn't consume one-time notices), block validity via `wp.blocks.parse` on the REST content of patterns/templates/parts (probe with heading/button/image — a `<div>` inside a paragraph is *not* flagged), Theme Check via its admin page, colour variations by writing the variation JSON (+`isGlobalStylesUserThemeJSON`) into the `wp_global_styles` post and resetting afterwards, mobile via `Emulation.setDeviceMetricsOverride` (desktop Chrome can't go below ~500px). Test posts with `.mov` cover videos wedge headless capture — skip them.

### Assets

- Fonts: `assets/fonts/{poppins,nunito}/*.woff2` — Google-served latin + latin-ext subsets with `unicodeRange` in theme.json; Poppins static 400–700, Nunito variable 300–800. OFL.txt alongside; credit in readme.txt.
- Abstract imagery: `.dev/abstract.py` generates `assets/images/abstract/*.svg` — a muted duotone ground, one geometric subject and fine white line work, sharing a stroke weight and light source so the ten read as one commissioned set. They replaced flat gradient blobs that rendered as smudges in the portfolio grid.
- Avatars: `.dev/avatars.py` generates `assets/images/avatars/*.svg` — duotone silhouettes, one muted ground and one figure tone each, with a different hair and shoulder shape per file so a row of four reads as four people. All ten share one neutral ground — per-avatar tints looked arbitrary side by side in a grid. Long hair is drawn *behind* the head and shoulders; anything drawn after the head is clipped to the skull, or it leaves a slab across the chin.
- Images: AVIF (`avifenc --min 20 --max 30 --speed 4`; `crowd.avif` at 34–44 because it sits under an 80% overlay). Sources were the 1.x JPGs; originals are gone from the repo (git history `1d3c10c` has them).
- `screenshot.png` (1200×900) is a headless-Chrome capture of the live front page with the test site's title/menu replaced in the DOM for the shot.

## Release checklist

1. `php -l` all PHP, validate JSON, bump `Version:` in `style.css` and `Stable tag` in `readme.txt`, add a CHANGELOG entry.
2. Activate on the Local site, load `/`, `/blog/`, a single post, `/author/…`, `/category/…`, `/tag/…`, a date archive, `?s=`, and (if WooCommerce is active) `/shop/`; render every pattern (`wp eval` loop over the registry) and check `wp-content/debug.log` (enable `WP_DEBUG_LOG` temporarily — remember to revert wp-config.php).
3. Run Theme Check from wp-admin (only expected notice: single text domain INFO).
4. Regenerate `languages/unapp.pot` and `screenshot.png` if strings or the hero changed.
