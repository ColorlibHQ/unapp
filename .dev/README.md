# Generator and audits

The patterns in `patterns/*.php` are generated, not hand-typed. Regenerate the
whole library with:

    for i in $(seq 1 24); do python3 .dev/batch$i.py; done
    python3 .dev/apply_grounds.py

`apply_grounds.py` runs last: it assigns each section its ground by role, which
the batches deliberately do not do, and then writes the page-opening variants
(`openings.py`): for every section that opens a starter page or a page starter,
a hidden `unapp/<slug>-h1` copy whose first heading is the page's h1, styled
exactly as the h2 it replaces. Starter pages hide their title, so that heading
is the page title; the section itself stays an h2 because it also appears
further down other pages.

## The measurement system

`pgen.py` holds every measurement the theme uses, and refuses anything off the
scale. Build sections from the components rather than passing numbers:

| Component | What it is |
| --- | --- |
| `section_std(inner, variation=, bg=, gradient=)` | a full-width section: padding 70, intro-to-content gap 60 |
| `card(inner)` | a surface: padding 50, gap 30, radius 20px |
| `stack(inner, gap=)` | a vertical run; also what makes an icon badge shrink to content |
| `grid(inner, cols=3\|4)` | a wide grid with the step-down utility class |
| `split(left, right)` | two columns at the house gutter, both carrying the stack gap |
| `icon_card(icon, title, body)` | badge, h3 and a paragraph |
| `card_title()` / `label()` | an h3 at `large`; the small uppercase line |
| `faq_list(pairs)` | Details cards in the reading column |
| `band(title, body, buttons)` | a closing call to action on the palette gradient |

Three radii exist in the theme: 14px (icon badges), 20px (cards and images),
999px (pills and avatars). Portraits are 96px in a grid, 56px beside a name.

## Audits

    python3 .dev/rhythm_audit.py            # ground rhythm of every composition
    python3 .dev/heading_audit.py           # exactly one h1 per composition, in its first section
    python3 .dev/link_audit.py              # every link on every starter page arrives somewhere
    python3 .dev/gradient_contrast.py       # every text on a coloured ground, in all 12 palettes
Run the repository checks together:

    python3 .dev/check.py

The WordPress integration suite runs inside an InnoDB transaction and rolls back
its test content. It loads Unapp for that process without activating the theme:

    wp --skip-themes --skip-plugins eval-file "$PWD/.dev/tests/import.php"

Use a local development installation with an administrator account. The suite
covers missing sections, save failures, recovery, duplicate submissions, public
contact details, read-only preview data, Undo and edit conflicts, launch checklist findings/review invalidation, contact-form selection, and AI review/apply with mocked HTTP responses. A Contact Form 7 smoke test also runs when a compatible copy is installed; it creates temporary forms without activating the plugin or submitting messages.

Browser keyboard regressions use Playwright installed outside the theme:

    npm install --prefix /tmp/unapp-browser --no-audit --no-fund playwright@1.62.1
    /tmp/unapp-browser/node_modules/.bin/playwright install chromium
    PLAYWRIGHT_MODULE=/tmp/unapp-browser/node_modules/playwright node .dev/tests/toggles.cjs

Set `CHROME_PATH` to an installed Chrome executable to use it instead. The
workflow in `.github/workflows/checks.yml` runs these checks and a minimum/current
WordPress and PHP matrix. Historical CDP spacing/wrap tooling mentioned in older
notes is not bundled in this repository; do not treat it as an available command.

## Artwork

    python3 .dev/avatars.py     # assets/images/avatars/*.svg
    python3 .dev/abstract.py    # assets/images/abstract/*.svg
    python3 .dev/showcase.py    # assets/images/showcase/*.svg

Showcase artwork is original, self-contained SVG: fictional product views,
packaging, identity studies and client websites. Edit the generator, then
regenerate assets before patterns. The screens gallery is hand-authored in
`patterns/screens.php` rather than generated by a batch.

The WebP scenes are generated fictional photographs. Exact prompts and encoding
settings live in `starter-photography.json`; keep them with changes to those
assets. Photographs are optimized to 1200 × 900, and the pattern generator reads
WebP dimensions to reserve image space before loading.

## Links

`buttons()` refuses a button without a destination. A link to a section uses
`home_anchor("slug")` (the section carries `anchor=` in `write_pattern`), since
sections recur across pages and footers render on all of them; transactions
the theme cannot perform go to the business's phone or email (`tel()`,
`mailto()`), directions to `map_link()`, and the shop and blog to `SHOP_URL`
and `BLOG_URL`, never a hard-coded path.

## Launch checklist UI checks

Generate an HTML fixture from the actual WordPress renderer while running the
transaction-isolated suite, then test it with the same Playwright setup:

    UNAPP_LAUNCH_PREVIEW_PATH=/tmp/unapp-launch.html wp --skip-themes --skip-plugins eval-file "$PWD/.dev/tests/import.php"
    UNAPP_LAUNCH_PREVIEW_PATH=/tmp/unapp-launch.html PLAYWRIGHT_MODULE=/tmp/unapp-browser/node_modules/playwright node .dev/tests/launch-ui.cjs

The browser test intercepts every request. It verifies desktop/mobile overflow,
keyboard interaction and both form payloads without contacting WordPress or
submitting a visitor's message. Set `UNAPP_LAUNCH_SCREENSHOT_DIR` to an existing
directory to capture the rendered screen at both widths.

## Starter visual checks

Export private previews from a local WordPress installation without activating
the theme. The exporter rolls back database writes. Set the output directory
first, then repeat the command for each starter slug in `inc/starter-sites.php`:

    mkdir -p /tmp/unapp-starters
    UNAPP_PREVIEW_STARTER=saas UNAPP_PREVIEW_OUTPUT=/tmp/unapp-starters UNAPP_PREVIEW_EDITOR=1 wp --skip-themes --skip-plugins eval-file "$PWD/.dev/render-starter.php"
    UNAPP_STARTER_PREVIEW_DIR=/tmp/unapp-starters PLAYWRIGHT_MODULE=/path/to/playwright node .dev/tests/starters.cjs

The browser serves exported HTML and local theme/core assets offline. It checks
320, 360, 390, 768 and 1280px layouts, touch targets, CTA destinations, images,
and the changed patterns against WordPress's real block save functions. Set
`CHROME_PATH` to use a system browser and `UNAPP_STARTER_SCREENSHOTS` to capture
full pages, hero views and thumbnail sources. `UNAPP_PREVIEW_PAGE` selects a
supporting page for export.

By default the browser suite expects all nineteen home exports. Use
`UNAPP_STARTERS=shop,restaurant,fitness` to run a subset. For Shop, use a separate
WordPress test installation with WooCommerce active, omit `--skip-plugins` and
set `UNAPP_PREVIEW_WOO=1`. Set `UNAPP_PREVIEW_SAMPLE_PRODUCTS=1` only in that
isolated installation to render four temporary product rows; the export rolls
them back. `UNAPP_EXPECT_SAMPLE_PRODUCTS=1` verifies those rows in the browser.
Editor checks cover the core-block patterns; WooCommerce collections are
verified through their actual server-rendered product rows.

## Starter finder and local-service starters

`batch23.py` generates Home Services, Cleaning and Salon & Barber. Their
supporting-page openings are listed in `openings.py`; keep their process sections
in `apply_grounds.py`'s soft-ground set. Photographs are bundled WebP assets with

Update the starter-card thumbnails from the rendered page, rather than using

## Publishing the public catalogue

Export the canonical starter and pattern inventory without retaining database writes:

```sh
UNAPP_CATALOG_OUTPUT=/tmp/unapp-catalog.json wp --skip-themes --skip-plugins eval-file .dev/export-catalog.php
```

The Colorlib documentation and product catalogue use this manifest. Keep all demo URLs, screenshot names and finder keywords in sync; do not maintain a separate hand-counted list. `.dev/publish-demo.php` refreshes only allowlisted Colorlibhub Unapp demos, preserves existing page IDs and requires a private backup directory in `UNAPP_DEMO_BACKUP`. It is an operator tool, excluded from release ZIPs. Never run it on customer sites. See [the 2.6.0 release record](../docs/releases/2.6.0.md) for publishing and verification.
